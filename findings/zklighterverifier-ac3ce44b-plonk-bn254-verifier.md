## What happens

This proxy runs zkLighter's PLONK proof verifier, which ends in a BN254 pairing check. With a quantum computer the setup secret follows from its fixed public points, so false proofs pass. The ZkLighter rollup, holding about 11,248 ETH and 463M USDC, calls this verifier.

## Evidence

- [Verify](https://etherscan.io/address/0x329d7d7f7b3f2879991b83e1a53bce6d7ce63e6f#code) checks a gnark PLONK proof and ends in a BN254 pairing call against fixed setup points.
- [ZkLighter](https://etherscan.io/address/0x3b4d794a66304f130a4db8f2551b0070dfcf5ca7) stores this verifier's address and holds about 11,248 ETH and 463M USDC.
- [The proxy](https://etherscan.io/address/0xac3ce44b6ff4e402858c99d5699ff63131572baa#code) takes a new verifier only from its master, a gatekeeper contract whose master is a 3-of-5 Safe.

## Reviewer notes

### Mechanism

Proxy 0xac3ce44b delegates every call to its target 0x329d7d7f (getTarget), ZkLighterVerifier, generated by gnark for the zkLighter circuit (line 25). Verify(bytes,uint256[]) (line 188) derives the challenges with SHA-256, folds the openings and ends in check_pairing_kzg, a staticcall to precompile 0x08 (line 904) against G2 setup points fixed in the code (lines 41-49). Whoever knows the setup's secret scalar can open commitments to anything, so a proof of a false statement verifies. Consumer: ZkLighter proxy 0x3b4d794a keeps this proxy in slot 4. Its implementation 0x9b4a5f3c is unverified; its bytecode delegatecalls to the address in slot 7 (0xa40ecafe), whose bytecode holds the Verify selector. Real transactions to ZkLighter succeed in the blocks before the pinned one. Fix path: Proxy.upgradeTarget (lines 56-61) sets a new target only for the master (Ownable.requireMaster), which is UpgradeGatekeeper 0x94da8a99 (unverified; startUpgrade and finishUpgrade selectors present; managedContracts(1) is this proxy). The gatekeeper's master is Safe 0x97a90ec9 with threshold 3 and five owners.

### Checks

- Header facts: this address alone, at block 26,438,999.
- Ruled out: a fixed verifier with no fix path: upgradeTarget lets the master repoint the proxy, and the master is a gatekeeper run by a 3-of-5 Safe; the gatekeeper's notice period was not read (unverified code).
- Ruled out: the value counted here: this proxy holds nothing; the ETH and USDC figures are ZkLighter's own balances, not this address's, and other tokens ZkLighter holds are not counted.
- Ruled out: sibling DesertVerifier 0x97521058 (ZkLighter slot 5) is a separate gnark PLONK verifier and its own row; ZkLighter's blob KZG opening is a separate finding.

### Questions

- ZkLighter's implementation 0x9b4a5f3c and its delegate 0xa40ecafe are unverified: what a batch accepted with a passing proof can change (state root, withdrawals of what ZkLighter holds) is read from bytecode only, so the funds-loss impact is not shown from source.
