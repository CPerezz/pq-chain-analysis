## What happens

This verifier checks Groth16 withdrawal proofs for a Tornado Cash fork against a verifying key hard-coded from Tornado's trusted setup. It accepts a proof when one BN254 pairing check passes, so a quantum attacker who recovers the setup trapdoor can forge proofs and withdraw pooled deposits.

## Evidence

- [verifyProof](https://etherscan.io/address/0xa9babc55c7da0eb203d082af0e5c1ad2c3f03743#code) returns true when a single BN254 pairing check passes.
- [verifyingKey](https://etherscan.io/address/0xa9babc55c7da0eb203d082af0e5c1ad2c3f03743#code) hard-codes the key from Tornado Cash's trusted setup ceremony.

## Reviewer notes

### Mechanism

verifyProof(bytes proof, uint256[6] input) (lines 200-238) decodes eight field elements into A, B and C (lines 204-214). It loads the constant key from verifyingKey() (lines 181-194). It builds vk_x = IC[0] + sum(input[i]*IC[i+1]) with Pairing.plus (precompile 6, line 87) and Pairing.scalar_mul (precompile 7, line 108). It then returns Pairing.pairing(-A, B, alfa1, beta2, vk_x, gamma2, C, delta2) (lines 228-237), which is one ecPairing call (precompile 8, line 151). The key comes from Tornado's setup ceremony (line 13). Anyone who knows the toxic waste (alpha, beta, gamma, delta, tau) can build A, B and C that pass for arbitrary public inputs (root, nullifierHash, recipient, ...). The calling pools then pay out a denomination for each forged nullifier. The contract has no owner or setter, and the key is pure code.
