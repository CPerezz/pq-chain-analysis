## What happens

OBLS approves a task when an aggregate BN254 BLS signature from operators with enough voting power verifies against their stored public keys. The keys are readable on-chain, so a quantum attacker who recovers them can sign any task and pass the quorum check.

## Evidence

- [verifySignature](https://etherscan.io/address/0xc7172c5dc062dedfaed4a91be7ae2f7c96b4b9aa#code) reverts unless the BLS pairing check of the aggregate key passes.
- [verifySingle](https://etherscan.io/address/0xc7172c5dc062dedfaed4a91be7ae2f7c96b4b9aa#code) runs the BN254 pairing precompile at address 8.
- [getOperatorBLSPubKey](https://etherscan.io/address/0xc7172c5dc062dedfaed4a91be7ae2f7c96b4b9aa#code) returns each active operator's stored BLS public key.

## Reviewer notes

### Mechanism

AttestationCenter.submitTask calls OBLS.verifySignature (lines 71-84). _calculateAggregatePK (245-267) sums voting power of the listed operator indexes and adds their stored G2 BLS keys (_calculateAggregatePKByBlsKeys, 269-295); line 81 requires the required voting power, line 82 calls BLS.verifySingle, which runs the BN254 pairing precompile (BLS.sol line 99). validateOperatorSignature (95-103) checks single-operator signatures the same way. Keys are public via getOperatorBLSPubKey (64-69), so recovering the private keys with a quantum computer lets an attacker produce a valid aggregate signature for any message; on Ditto's AVS an approved task submits an arbitrary user operation through Ditto's hook.
