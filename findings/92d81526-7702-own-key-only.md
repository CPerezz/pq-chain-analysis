## Summary

unnamed 7702 delegate: EIP-7702 delegate logic whose signed path accepts only the account's own key (recovered == address(this)). Under EIP-8151 it fails only if the account later holds real code.

## Mechanism

PQ-20. As a 7702 delegation they keep working: EIP-8151 exempts delegation indicators. An account that takes this logic as real code can no longer authorise anything, and with code it cannot send transactions (EIP-3607), so what it holds is locked.

## Evidence

- How it was placed: the code accepts only the signature of the account it runs in. As 7702 delegate code it is not affected. An account that took this logic as real code could not sign for itself. Rule: self-only.
- heimdall decompile of the delegate target 0x26ca1304cf40c1c3514dc38c8163e6806be73ae5: "Invalid signature" require on recovered == address(this)
- cast code at 26438999: 0xef010026ca1304cf40c1c3514dc38c8163e6806be73ae5; the target code hash equals facts.representative_code.h; delegations are exempt from EIP-8151

## Impact and exposure

- Value held at block 26,438,999: $70,739 (ETH and 49 priced tokens, over 36 addresses).
- Activity: 2,007 transactions called it in the 90 days before that block; last on 2026-11-18.

## Remediation

Keep the 7702 delegation, or re-delegate to logic that accepts the account's key while it has code / ERC-1271.
